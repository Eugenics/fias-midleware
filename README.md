# FIAS middleware

Инфраструктура для соседних проектов `../fias-parser` и `../fias-downloader`:
Docker Compose запускает GeoServer, PostGIS, веб-клиент карт и Grafana.
Сами parser, downloader и Prometheus в этот стек не входят.

## Сервисы

| Сервис | Назначение | Адрес с хоста |
| --- | --- | --- |
| `map-client` | Карта на OpenLayers | http://localhost:8080 |
| `geoserver` | Публикация геоданных и WMS | http://localhost:8181/geoserver/ |
| `postgis` | PostgreSQL с расширением PostGIS | `localhost:5435` |
| `grafana` | Мониторинг загрузчика FIAS | http://localhost:3000 |

## Быстрый запуск

Нужны Docker Engine с Docker Compose и GNU Make. Команды выполняются из корня
репозитория. Node.js на хосте для запуска через Docker не требуется.

Чтобы собрать и запустить карту вместе с GeoServer и PostGIS:

```sh
make map-up
```

Откройте http://localhost:8080. Первый запуск GeoServer может занять некоторое
время; если каталог ещё недоступен, дождитесь запуска и нажмите «Обновить».

Для запуска всего стека, включая Grafana, нужна внешняя сеть
`fias-downloader-network`. Если её ещё не создал соседний проект:

```sh
docker network create fias-downloader-network
```

Затем запустите сервисы:

```sh
make compose-up
```

Prometheus должен быть подключён к этой сети и доступен по адресу
`http://fias-downloader-prometheus:9090`. Без него Grafana запустится, но панели
не получат данные.

## Работа с картой

1. Опубликуйте слой или группу слоёв в GeoServer.
2. Откройте веб-клиент и нажмите «Обновить», если каталог уже был загружен.
3. Включите слой флажком. При включении первого слоя карта приблизится к его
   границам, если они заданы в каталоге.
4. Нажмите на объект на карте. Откроется модальное окно с атрибутами в таблице
   **«Поле | Значение»**, сгруппированными по слоям и объектам.
5. Закройте окно кнопкой «Закрыть» или клавишей Escape.

Доступны поиск слоёв, настройка прозрачности, легенда и кнопка «К слою».
Последний включённый слой отображается сверху. «Обновить» перечитывает каталог
и сбрасывает выбор слоёв. Длинное содержимое модального окна прокручивается.

Информация об объектах запрашивается у включённых queryable-слоёв через
GetFeatureInfo в формате JSON, до 10 объектов на слой. В окне также отображаются
состояние поиска, отсутствие объектов и ошибки получения информации.

Фоновая сетка не является картой: включите опубликованный слой или группу.
Внешняя картографическая подложка не используется. Клиент рассчитан на WMS-слои,
доступные для чтения без входа; администрирование выполняется в GeoServer.

Клиент получает каталог через GetCapabilities. Карта и запросы GetMap и
GetFeatureInfo используют `EPSG:900913`; границы слоёв преобразуются из
`EPSG:4326`. Nginx раздаёт сборку и проксирует `/geoserver/wms` на
`geoserver:8080`, поэтому отдельная настройка CORS не требуется.
OpenLayers включён в сборку, CDN в браузере не нужен.

После изменения файлов `web/` пересоберите клиент:

```sh
make map-up
```

## Настройка PostGIS в GeoServer

В интерфейсе GeoServer создайте хранилище PostGIS:

| Параметр | Значение |
| --- | --- |
| Host | `postgis` |
| Port | `5432` |
| Database | `geoserver` |
| Schema | `public` |
| User | `geoserver` |
| Password | Значение `POSTGIS_PASSWORD`, по умолчанию `geoserver` |

Из контейнера GeoServer используется адрес `postgis:5432`, а с хоста —
`localhost:5435`. Расширение PostGIS инициализируется образом автоматически.
Хранилища и публикация слоёв настраиваются отдельно в GeoServer.
В Compose также включена установка расширения CSS для GeoServer.

## Конфигурация

Переменные можно задать в окружении или в локальном файле `.env` рядом с Compose:

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `MAP_CLIENT_PORT` | `8080` | Порт веб-клиента на хосте |
| `POSTGIS_PASSWORD` | `geoserver` | Пароль БД при первой инициализации |

Пример запуска карты на другом порту:

```sh
MAP_CLIENT_PORT=8082 make map-up
```

Параметры инициализации PostgreSQL применяются только к пустому тому. Изменение
`POSTGIS_PASSWORD` не меняет пароль пользователя в уже созданной БД.

Grafana настроена с локальными учётными данными `admin` / `admin`.
Перед внешним доступом замените стандартные пароли и ограничьте доступ к портам,
включая опубликованный порт PostgreSQL `5435`. Не сохраняйте реальные секреты
в репозитории.

## Мониторинг

Grafana автоматически загружает источник данных Prometheus с UID `prometheus`
и дашборд «FIAS Downloader — текущая загрузка». На нём отображаются активная
загрузка, прогресс, загруженный объём, размер файла и изменение объёма во времени.

Настройки находятся в `deploy/grafana/provisioning/`, дашборд —
в `deploy/grafana/dashboards/fias-downloader.json`. Изменения дашборда сохраняйте
в этом JSON, чтобы они воспроизводились при развёртывании.

## Импорт OSM

В Makefile есть команда:

```sh
make import-osm
```

Она запускает `geofabric/imposm/imposm` с конфигурацией
`geofabric/imposm/mapping.yml` и всеми файлами `geofabric/pbf/*.pbf`
(без обхода подкаталогов, в порядке имён файлов).
Перед запуском убедитесь, что эти файлы доступны, бинарник исполняемый,
а PostGIS запущен.

Текущая команда использует `localhost:5435`, БД и пользователя `geoserver`
с локальным паролем `geoserver`. Первый файл читается с `-overwritecache`,
остальные добавляются в общий кэш с `-appendcache`. После чтения всех файлов
один раз выполняется запись в БД и развёртывание таблиц с `-deployproduction`.
При отсутствии файлов или ошибке чтения команда останавливается до записи в БД.
Чтобы добавить регион, положите его PBF в `geofabric/pbf/`;
при другом пароле скорректируйте команду в Makefile.
Импорт не публикует слои в GeoServer автоматически.

## Управление и диагностика

| Команда | Действие |
| --- | --- |
| `make help` | Список команд |
| `make map-up` | Сборка и запуск клиента с зависимостями |
| `make map-logs` | Последние 100 строк логов клиента и наблюдение за новыми |
| `make compose-up` | Запуск всех сервисов в фоне |
| `make compose-down` | Остановка и удаление контейнеров с сохранением данных |
| `make compose-rebuild` | Удаление контейнеров и именованных томов, затем запуск со сборкой в переднем плане |
| `make import-osm` | Импорт OSM в PostGIS |

```sh
docker compose ps
docker compose logs --tail=100 geoserver
docker compose logs --tail=100 postgis
docker compose logs --tail=100 grafana
```

Если каталог пуст, проверьте публикацию слоёв в GeoServer. При ошибке получения
атрибутов проверьте поддержку GetFeatureInfo JSON для слоя. Если панели Grafana
пусты, проверьте доступность Prometheus из сети `fias-downloader-network`.

## Хранение данных и сети

| Данные | Место хранения |
| --- | --- |
| Grafana | Именованный том `grafana-data` |
| PostgreSQL/PostGIS | Именованный том `postgis-data` |
| Конфигурация и данные GeoServer | Каталог `./var/geoserver` |
| Кэш GeoWebCache | Каталог `./var/geoserver-blobstore` |

**`make compose-rebuild` удаляет данные Grafana и PostGIS в именованных томах.**
Каталоги GeoServer в `var/` этой командой не удаляются. Для обычного обновления
клиента используйте `make map-up`.

GeoServer, PostGIS и клиент работают в сети `fias-geoserver-network`, которую
Compose создаёт и удаляет вместе со стеком. Grafana использует внешнюю сеть
`fias-downloader-network`; Compose её не создаёт и не удаляет.

## Разработка и проверки

Для локальной проверки клиента нужны Node.js 22 и npm:

```sh
cd web
npm ci
npm test
npm run build
```

Тесты используют встроенный Node test runner. Сборка Vite помещается в
`web/dist/`. Для просмотра с прокси к GeoServer используйте `make map-up`.

Из корня репозитория:

```sh
docker compose config --quiet
python3 -m json.tool deploy/grafana/dashboards/fias-downloader.json > /dev/null
```

Проверка Compose не запускает сервисы. После изменения дашборда дополнительно
проверьте логи Grafana и отображение панелей с работающим Prometheus.

## Структура проекта

```text
.
├── docker-compose.yml       # Сервисы, сети, порты и тома
├── Makefile                 # Команды управления
├── web/                     # OpenLayers, тесты, Vite, Dockerfile и Nginx
├── deploy/grafana/          # Provisioning и дашборды
├── geofabric/               # Imposm, mapping и исходные OSM-данные
└── var/                     # Данные GeoServer и кэш GeoWebCache
```
